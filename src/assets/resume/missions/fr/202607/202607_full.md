Le serveur **MCP** implémenté sur la mission est ce qui donne à l’agent prise sur le système d’information.
  - Les _tools_ et _resources_ exposés permettent de piloter l’ensemble des registres : services **SOAP**, **REST**, serveurs **MCP** et agents **A2A**.
  - La connexion au serveur MCP est sécurisée par **OAuth** et exposée au travers d’**APIM**.

Le pipeline **RAG** indexe un repository GitHub hébergeant les fichiers **OAS** du système d’information.
  - Le **semantic chunking** découpe les spécifications en fragments cohérents plutôt qu’à taille fixe.
  - Le **multi query retrieval** et l’**hybrid search** améliorent significativement le rappel sur des questions formulées librement.
  - Les vecteurs sont stockés dans **pgvector**.

Plusieurs mécanismes rendent l’agent utilisable en production sur la durée.
  - Une **mémoire de session** conserve le fil de la conversation d’un échange à l’autre.
  - Des **guardrails** dédiés empêchent le détournement de l’agent hors de son périmètre d’assistance aux ressources du registre.
  - Une **compaction des messages** réduit le contexte transmis au modèle sur les conversations longues.

L’ensemble tourne sur un cluster **AKS** et consomme les modèles servis par **Azure AI Foundry**.
  - Plusieurs modèles sont mobilisés selon l’usage : **GPT-5.4** et **Terra** pour le chat, **Luna** pour les guardrails et **text-embedding-3** pour les embeddings.

**Technologies utilisées :**
```text
Java 21, SpringBoot, Spring AI, MCP, A2A, RAG, pgvector, PostgreSQL, OAuth2, APIM, Azure AI Foundry, AKS, Angular, Github Actions
```
